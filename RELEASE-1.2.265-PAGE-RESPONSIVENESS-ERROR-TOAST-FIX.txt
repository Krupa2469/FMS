Rose Gardens RGMS 1.2.265 - Page Responsiveness and Error Toast Fix

Reason for this hotfix
- Production screenshots from Web v1.2.264 showed a generic "Unable to complete the requested action" toast on the Admin Masters home.
- The Association Dashboard could trigger Chrome's "This page isn't responding" dialog while rendering.

Corrections
1. Resident dropdown sorting no longer rewrites an already-sorted <select>.
   The previous global MutationObserver could react to its own replaceChildren mutation repeatedly.
2. Dashboard card-fit no longer measures scrollWidth one pixel at a time.
   Font sizing remains with the existing dashboard/module CSS; global JS now enforces only centering and containment.
3. MutationObservers are requestAnimationFrame-coalesced so one render produces at most one consistency pass per frame.
4. Background Firebase/auth/bootstrap Promise rejections are logged but do not create misleading generic user toasts.
   CRUD failures continue to surface through rgms:data-error and per-form messages.
5. Admin Masters no longer waits for the entire all-collection startup bootstrap before becoming interactive.
6. Association and Colony Fund dashboard initializers reuse the authoritative snapshot just loaded by navigation for up to 10 seconds, avoiding immediate duplicate Firestore reads.
7. Existing v1.2.264 CRUD, full-screen filtered registers, normalized residents, alphabetical resident dropdowns, clickable-number alignment and Telugu-first bilingual Fund Summary remain retained.
