Rose Gardens RGMS 1.2.245 - Consolidated Web Release
=====================================================

This release is based on Rose-Gardens-Web-1.2.241-Association-Colony-Dashboard-Calculation-Init-Fix-24 and consolidates the approved corrections requested after that build.

Key changes
-----------
1. Resident login displays Name only; the OTP is sent to the mobile mapped to that Resident in Firestore. The mobile number is not displayed/editable and the verified Firebase phone must match the selected Resident.
2. Resident My Profile loads/saves DOB, anniversary, email, blood group, occupation, emergency contact and remarks through secured Firebase callable functions, with user-friendly messages.
3. Resident Dashboard can ask for location permission; live location is used for weather/air/rain/nearby services. Location is not saved to Profile or Firestore. Maps fall back to "Rose Gardens, Cheeryal, Keesara, Medchal, Telangana".
4. Resident Home card labels, Colony Payments and Bill Payment cards use consistent responsive/light styling.
5. Association and Colony Fund dashboards use one authoritative first-open calculation path and current Firestore data. No page refresh is required for initialization.
6. Dashboard figures are clickable. Drill-downs open only the filtered records represented by the clicked number/amount.
7. Ganesh Collection report contains three sections: Contributions, Expenditure and Sponsors. Sponsor count is shown in the summary and sponsor drill-down/dashboard card is clickable.
8. Ganesh contribution report uses April-March FY logic and actual transaction date as authoritative, preventing valid rows from being omitted because of stale FY metadata.
9. Laddu Auction includes Payment Status: Paid / Unpaid in entry, register, report/export and related calculations.
10. Applicable registers/forms provide full Firestore CRUD controls; successful writes are followed by a fresh Firebase reload. Live data never falls back to packaged JSON, localStorage, or historical Firestore alias collections.
11. Resident-linked forms display Name only in dropdowns; H.No. is populated from Residents Master and is not appended to dropdown labels.
12. Residents Master is the canonical source for displayed resident names across registers/reports/transactions wherever the resident can be resolved.
13. Resident-based registers and reports sort alphabetically by Name, with H.No. as a secondary key, and use the column order S.No. -> Name -> H.No. -> remaining fields.
14. PDF/Excel/JPEG/on-screen report data use the same filtering, sorting and totals.
15. Layout, font stack and user-facing status/error messages are normalized throughout the application.

Firebase deployment
-------------------
If resident profile / mapped OTP callable functions have not yet been deployed from this source tree, deploy them before/with Hosting:

  export FUNCTIONS_DISCOVERY_TIMEOUT=60
  firebase deploy --only functions:residentLoginPhone,functions:getResidentProfile,functions:updateResidentProfile
  firebase deploy --only hosting

All existing working modules (role access, officer login, Razorpay, WhatsApp/SMS, BBPS, reminders/greetings, Masters, reports/exports and Firestore data model) are retained.
