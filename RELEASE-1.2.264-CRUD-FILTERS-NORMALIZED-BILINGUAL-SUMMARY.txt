Rose Gardens RGMS 1.2.264 - CRUD, Full-Screen Filters, Normalized Residents and Bilingual Fund Summary

1. CRUD / user feedback
- All Store insert/update/replace/delete/bulk-save operations retain verified Firebase writes.
- Successful CRUD emits the global friendly success toast plus existing form-level status where present.
- Final Firebase CRUD failures emit a friendly error toast even when a module catches the rejected operation.
- Runtime and unhandled Promise failures remain surfaced to the user.

2. Filtered registers
- Association, Residents, Colony Fund and Ganesh dashboard drill-down registers display full-screen.
- Colony Fund now consistently adds/removes its drill-down state and hides the background dashboard/tabs/forms while a filtered register is open.
- Complaints, Visitors, Documents, Meetings and General Information filtered registers display full-screen and hide background cards/forms.
- The filtered-register Close control clears the active dashboard filter by selecting the module's Total card instead of navigating away.
- Report drill-down registers remain full-screen with Close control.

3. Dashboard layout / clickable numbers
- Dashboard values are center aligned with tabular numerals.
- A runtime fitting guard reduces the figure font only when needed so large currency values remain inside the card instead of clipping or overflowing.
- The fitting guard also covers simple summary-card numeric spans, not only elements already carrying dashboard-number classes.

4. Resident dropdowns / normalization
- Residents Master is the authoritative source for resident pickers.
- Resident names are whitespace-normalized and alphabetically sorted, with H.No. as tie-breaker where applicable.
- H.No. is canonicalized to the application format (2-1/<number>) on writes so dashboards, payments and reports use the same house key.
- Distinct Firestore documents are preserved even when a legacy Resident ID is duplicated.
- Occupation Status is canonicalized everywhere to Owner / Tenant / Vacant. Legacy Occupied records are resolved from Resident Type on read.
- Resident Type is canonicalized to Owner / Tenant / Family Member.
- Admin Residents Master now uses the same Owner / Tenant / Vacant Occupation Status values as the main Residents Master.
- Writes retain status=Occupied/Vacant as a compatibility field while occupationStatus remains canonical.

5. Bilingual Fund Summary report
- Reports option: Colony + Ganesh Fund Summary (Telugu / English).
- Telugu labels are displayed above English labels.
- Colony Fund Summary fields, each shown for Current FY and Current Month:
  Total Houses (Occupied / Vacant), Total Expected Fund, Collected Fund, Pending Fund, Expenditure, Balance.
- Section report header: Colony Fund Summary (Telugu above English).
- Ganesh Festival Fund Summary retains the existing summary fields/calculations.
- Section report header: Ganesh Festival Fund Summary (Telugu above English).
- The bilingual content continues through on-screen display and PDF/Excel/JPEG export paths.

6. Verification scope
- Static JavaScript syntax, action-handler references, CRUD notification safeguards, filtered-register hooks, resident dropdown normalization and bilingual report markers are audited in QA-AUDIT-1.2.264.txt.
- Live Firebase permission/data-write verification still depends on the deployed Firebase project and authenticated runtime session.
