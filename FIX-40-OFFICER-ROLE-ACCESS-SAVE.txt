Rose Gardens Web 1.2.258 — Officer Role Access Save Fix

Fixes:
1. Role Access Save/Update now works for an office-bearer when the CURRENT Role Access matrix grants that officer role Role Access Master -> Update.
2. Role Access verification compares actual YES/NO permission values instead of JSON key order, preventing false "does not match" errors after Firestore reorders nested map keys.
3. The Admin module now reloads the Role Access matrix for every authenticated office-bearer who opens the module, instead of leaving non-Admin sessions on default permissions.
4. Role Access form buttons are rebound safely each time the Admin module is reopened.
5. Fixed the Service Provider Master initialization error "providerSearch is not defined" by using explicit DOM lookups.
6. Updated Firestore rules permit a non-Admin officer to update settings/roleDashboardAccess only when their CURRENT role permissions explicitly allow Update or Reset. Deleting the entire Role Access settings document remains Admin-only; other Settings remain Admin-only.

IMPORTANT: deploy the included updated firestore.rules before testing an officer Save/Update.
